# CLAUDE.md — Agent Reference for virt-k8s

## What this repo is

A live home-lab Kubernetes cluster managed with **GitOps (FluxCD)**. The cluster runs on **Talos Linux** VMs inside Proxmox on a Minisforum MS-01. Configuration is generated from a single `cluster.toml` file via **makejinja** templates.

**Template source:** based on [onedr0p/cluster-template](https://github.com/onedr0p/cluster-template).

## Directory structure

```
bootstrap/          Helmfile bootstrap (runs before Flux takes over)
docs/               Operational docs: storage benchmarks, useful commands, volsync restore
.github/            GitHub Actions workflows; template E2E tests
kubernetes/         FluxCD-managed manifests (desired cluster state)
  apps/             Per-namespace application HelmReleases
  components/       Reusable Kustomize components (volsync, gpu, sops, http-scale-to-zero)
  flux/             Flux entrypoint Kustomizations
talos/              Talos machine config patches and node topology
template/           Jinja2 templates + makejinja plugin that render bootstrap/ and kubernetes/
.mise/config.toml   Pinned CLI tool versions (kubectl, flux2, talosctl, sops, helm, etc.)
justfile            Task runner entry point; delegates to sub-modules
makejinja.toml      Template engine config; reads cluster.toml, renders *.j2 files
cluster.toml        (gitignored) live cluster config — generated by `just init`
```

## Common just commands

```sh
just configure          # Render templates from cluster.toml → live files
just init               # Generate cluster.toml, age key, deploy key, webhook token
just bootstrap:talos    # Bootstrap Talos on all nodes
just bootstrap apps     # Install cilium, coredns, spegel, flux; sync cluster
just talos:generate-config   # Regenerate Talos configs
just talos:apply-node IP=? MODE=?  # Apply config to a node
just talos:upgrade-node IP=?       # Upgrade a node to newer Talos
just talos:upgrade-k8s             # Upgrade Kubernetes version
just talos:reset                   # Reset nodes to maintenance mode
just reconcile          # Force Flux to sync git state
just template:tidy      # Remove template directory after setup is complete
```

## Secrets management

- **Tool:** SOPS with an age key
- **Key file:** `age.key` (gitignored, path set via `SOPS_AGE_KEY_FILE` env var in `.mise/config.toml`)
- **Rules:** `.sops.yaml` — encrypts all of `talos/`, encrypts `data`/`stringData` keys in `bootstrap/` and `kubernetes/`
- **Encrypted files** follow the pattern `*.sops.yaml` — never commit a plaintext secrets file

---

## GitOps flow (Flux)

1. Flux root: `kubernetes/flux/cluster/ks.yaml` — single `Kustomization` named `cluster-apps`
2. Points to `kubernetes/apps/` — all namespaced HelmReleases live here
3. SOPS decryption is configured at the root Kustomization level
4. All child `HelmRelease` resources are patched with retry/remediation strategies

Namespaces in use: `kube-system`, `cert-manager`, `flux-system`, `network`, `databases`, `default`, `observability`, `openebs-system`, `rook-ceph`, `volsync-system`.

---

## Template system

- Source files live in `template/config/` mirroring `bootstrap/` and `kubernetes/` with `.j2` suffix
- `makejinja.toml` reads `cluster.toml` (Pydantic-validated) and renders all `.j2` files
- Plugin code: `template/scripts/plugin.py` (Jinja2 filters + cluster config model)
- Validation: `template/scripts/validate.py` / `test_validate.py`
- Run `just configure` after editing `cluster.toml` to regenerate live files

## Conventions

- All secrets use SOPS age encryption — never edit `*.sops.yaml` files directly; use `sops <file>`
- Template files end in `.j2`; rendered outputs live in the same path without `.j2`
- Renovate runs on weekends and auto-merges minor/patch updates on branches
- GitHub Actions workflows use `zizmor` for security linting (enforced via lefthook pre-commit)
- Talos configs are assembled by `topf` from patches in `talos/all/`, `talos/control-plane/`, and per-node directories
- `TODOS.md` tracks in-progress work and known bugs

## Things to know

- `github-push-token.txt` exists at repo root — this is a sensitive file, do not log or expose its contents
- `kubeconfig` and `age.key` are gitignored generated files; set by mise env vars automatically
- The cluster uses Tailscale operator for VPN access and Cloudflare Tunnel for external exposure
- `cloudnative-pg` manages PostgreSQL for immich and nextcloud with barman-cloud S3 backups
- `volsync` + `kopia` handle PVC backups; see `docs/volsync-restore.md` for the restore procedure
- Scale-to-zero is implemented via KEDA HTTP add-on for applicable apps
